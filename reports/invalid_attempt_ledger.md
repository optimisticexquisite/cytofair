# Excluded-attempt ledger

No attempt was excluded for its score or direction. The raw JSONs named below remain
under `results/attempts/`; the confirmatory summarizer reads only
`results/classification/*.json`.

## Split-library data-integrity failure

An initial ResNet-18 launch inherited scikit-learn 1.7.2 from the node's base
environment. That release generated P2 training counts of 3,214, 3,237, 3,215,
3,236, and 3,223 across seeds 17/29/43/71/101 instead of the frozen 3,239/810
assignment generated by scikit-learn 1.9.0. Consequently P1′ was no longer identical
to P1 and had those same reduced training counts. This is a predefined data-integrity
failure, not a model failure.

The launcher was stopped after 12 twenty-epoch JSONs existed: all five P1 runs, all
five incompatible P1′ runs, and P2 seeds 17 and 29. The P2 JSONs record 3,214/835 and
3,237/812 train/test crops. None enters a summary or p-value. They are retained in:

- `results/attempts/classification_sklearn_1.7.2/`

The corrective action was to pin Python ≥3.11 and scikit-learn 1.9.0, generate and
hash all 20 split files locally and remotely, add split/image library versions to run
metadata, and restart the complete 120-run matrix from zero at Git commit `4da9f62`.
The final matrix validator confirms 120/120 files use 3,239/810 crops and match the
released semantic split hashes.
